# 🌱 트랜잭션 경계 설계

> 3.5 실패와 트랜잭션 고려하기 에서 뻗음
> 상태: 씨앗

## 왜 궁금해졌나

`@Transactional` 붙이면 되는 줄 알았는데,
**메일 발송 실패로 회원가입이 롤백되는 건 예상 못 했다.**
그럼 뭘 트랜잭션 안에 넣고 뭘 빼야 하지?

## 파고들 질문

- [ ] `@Transactional`은 어떤 예외에 롤백하나 (Checked vs Unchecked)
- [ ] `rollbackFor`, `noRollbackFor`는 언제 쓰나
- [ ] try-catch로 잡으면 정말 롤백이 안 되나? (그런데 왜 안 되는 경우가 있지)
- [ ] 트랜잭션 전파(Propagation) — REQUIRES_NEW는 언제
- [ ] 트랜잭션 안에서 외부 API를 호출하면 왜 위험한가
      (커넥션을 붙잡고 있는 시간 = 커넥션 풀 고갈?)
- [ ] 그럼 메일 발송 같은 건 어디로 빼야 하나 (이벤트? 작업 큐?)
- [ ] 외부 API는 성공했는데 DB가 실패하면? (→ 4장에서 다룸)
