# 🌱 별도 캐시 서버 구성하기

> 3.3 몇 가지 조회 성능 개선 방법 에서 뻗음
> 상태: 씨앗

## 왜 궁금해졌나

"DB 확장보다 캐시가 싸다"는 건 알겠는데,
그럼 **언제 캐시를 넣기로 결정**하는 거지?
그리고 캐시를 넣으면 코드가 어떻게 바뀌지?

## 파고들 질문

- [ ] 레디스는 왜 빠른가? (메모리? 싱글스레드?)
- [ ] 무엇을 캐시하고 무엇을 캐시하면 안 되나?
- [ ] 캐시된 데이터가 바뀌면 어떻게 하나 (무효화 전략)
- [ ] TTL은 어떤 근거로 정하나?
- [ ] 캐시 미스가 몰리면? (Cache Stampede)
- [ ] 로컬 캐시 vs 원격 캐시, 언제 뭘 쓰나
- [ ] 캐시 서버가 죽으면 서비스는 어떻게 되나

## 도입 경험이 있다면 물어볼 것

- [ ] 캐시를 넣기로 한 **결정적 지표**는 무엇이었나 (응답시간? DB CPU?)
- [ ] 넣고 나서 실제로 얼마나 좋아졌나
- [ ] 캐시 때문에 생긴 **새로운 장애**는 없었나
- [ ] 다시 한다면 다르게 할 부분은?
